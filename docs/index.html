THE QUESTION

What exactly changes when token i becomes token i + 1?

↳

Each layer makes a fresh K and V for the new token. Old rows stay put. The new query reads them all, then the cache grows by one.

02 / FOUR DESIGNS

Same context.
Different memory shapes.

All four keep enough information for past tokens to influence the next one. They differ in how much K/V state each layer stores.

CACHE FOOTPRINT · TWO LAYERS

Every generated token adds another slice.

Illustrative storage only: tensors × bytes per value. We exclude allocator padding, quantization scales, and temporary workspaces.

ƒ
Count what is stored, not what is computed.

MHA/GQA/MQA store K + V. MLA stores a compressed cKV vector and a small decoupled RoPE key; its per-token cache can be much smaller even though it reconstructs K/V features to compute attention.

03 / THE CONTEXT EDGE

What happens
when the cache is full?

“Context length” is a model and runtime limit, not one universal cache rule. The next-token prediction is still available; processing that next token requires a policy.

The final in-range token writes the final row. At that moment, attention can read all rows from position 0 through position 7.

A

Stop, reject, or ask for a shorter prompt

A strict max-position check can block another decode step. The full cache remains unchanged; the system can stop generation or truncate input before starting.

STRICT LIMIT
B

Slide a fixed-size window

Evict the oldest K/V row as a new row arrives. Memory stays bounded, but tokens outside the window can no longer be attended to directly.

WINDOWED
C

Use a model designed for longer context

Some systems extend positional handling or combine recent tokens with selected “sink” tokens. These are architecture/runtime choices; a cache does not grow safely forever by itself.

MODEL-DEPENDENT
Token i + 1 is not in the cache yet.

The model has used token i to predict it. Only after token i + 1 is fed through each decoder layer are its K and V appended.

04 / THE MENTAL MODEL

Read. Match.
Gather. Append.

Every layer owns its own cache. The cache is not one summary vector for the conversation: it is a stack of per-token K/V state, organized by layer and KV head.

Open the source notes ↗
01Project the current hidden state

Make Q, K, and V. RoPE rotates query/key dimensions using the token position.

02Read old keys and values

Compare the new query against every visible key. Softmax turns those scores into weights for the values.

03Finish the block

Mix values, apply output projection and MLP, then pass the result to the next layer.

04Keep this token for later

Each layer retains its new K/V representation. The next token can now attend to it.

Scope of this playground

Small, randomly initialized weights; 32-wide hidden state; 4 query heads; two decoder layers by default. The demo runs the arithmetic on a CUDA GPU and serializes rounded trace values for this page. It teaches tensor flow and cache accounting, not trained-model behavior or speed.
