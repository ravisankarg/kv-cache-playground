01 / THE FOUNDATIONS

How context becomes
the next token.

A decoder takes a sequence of token IDs and returns a probability distribution over the next ID. A user question and retrieved context become parts of that same sequence, separated by the prompt format.

1.1 A prompt is a sequence, not two memory systems

Here the template is <bos> context : … user : … ? assistant :. The context provides three key/value facts; the question names two keys. The decoder must emit their two values in order, then <eos>. The three key slots are fixed in order; training shuffles the values, so “france” cannot be answered correctly by always recalling “paris”. These are synthetic assignments, not geography claims.

xt = E[tokent] + P[t] ∈ ℝ32   →   block₁   →   block₂   →   z = RMSNorm(ht) Wvocab ∈ ℝ23
p(next = j | prefix) = exp(zj/τ) / Σk exp(zk/τ)

E is a learned token embedding table; P is a learned position table, and RoPE also acts on Q/K in each block. z contains one logit per vocabulary ID. Temperature τ changes the distribution; this lab uses τ = 1 and chooses the largest probability (greedy decoding). EOS is learned like any other token; the runtime decides to stop when it is selected.

1.2 Attention is a weighted retrieval operation

Each layer transforms its current hidden vector into a query (what to match), a key (how this position can be matched), and a value (what to retrieve). Each of the four heads has width 8. A key is not a word label; it is a learned numeric representation of a token and its preceding context.

ut = ht / √(mean(ht²) + ε)
qt,h = RoPEt(utWQ,h),   kj,h = RoPEj(ujWK,h),   vj,h = ujWV,h
st,j,h = qt,h · kj,h / √8 + Mt,j,   at,:,h = softmax(st,:,h)
ot,h = Σj≤t at,j,hvj,h;   Mt,j = 0 if j ≤ t, otherwise −∞

Softmax converts relative scores into positive weights summing to one. Scaling by √8 helps control score magnitude as head width grows. The causal mask makes future-token weight exactly zero; it allows the current token to attend to itself. Decode enforces the same mask by making only past and current rows available. Why two layers, residuals, and an MLP matter

Layer 1 can mix a fact’s key with its value, and mix the requested keys into the question representation. Layer 2 reads keys/values projected from those already contextualized layer-1 outputs. Its cache therefore differs from layer 1’s. A residual connection retains the incoming representation while attention adds retrieved information. The MLP transforms each position independently; it does not read other cache rows.

r = h + concat(o₁, …, o₄)WO
h′ = r + [SiLU(RMSNorm(r)Wgate) ⊙ RMSNorm(r)Wup]Wdown
SiLU(x) = x · sigmoid(x)

This toy uses two pre-norm blocks, a width-64 gated MLP, no dropout at inference, and a final RMSNorm and vocabulary head.

Position is part of attention: the RoPE rotation

For one adjacent pair of dimensions, multiply Q and K by a rotation with angle tθ. Their dot product depends on relative position: (Rtq)ᵀ(Rjk) = qᵀRj−tk. Old rotated keys can stay in the cache while the new query uses its own position. Deleting an old row does not reset the remaining positions.

Rt = [[cos(tθ), −sin(tθ)], [sin(tθ), cos(tθ)]]
θi = 10000−2i/dh

1.3 Prefill, decode, and a full context window

Prefill processes the known prompt: all its positions can run together within a layer using the triangular causal mask. It writes K/V for each prompt position into each layer. Only the final prompt position’s logits are needed for the first generated token. Decode feeds that chosen token through both layers, appends its own K/V, and produces the following distribution. Old causal hidden states cannot change when a future token arrives, so their K/V can be reused exactly.

Prefill: Q,K,V ∈ ℝT×H×dh, attention per head ∈ ℝT×T
Decode: Q ∈ ℝ1×H×dh, cached K,V ∈ ℝ(T+1)×H×dh
Dense attention arithmetic: prefill O(T² H dh); one decode step O(T H dh)
MHA cache bytes = 2 · batch · layers · T · KV_heads · head_width · bytes_per_scalar

KV reuse removes repeated prefix projections and MLP work. It does not remove the need to read prefix K/V for dense attention. Decode often has less matrix reuse and greater bandwidth pressure; these operation counts are not timing measurements.

LAB 01C

At the final slot

Untrained CUDA architecture trace

A model/runtime cap, an attention-window size, and a VRAM budget are different limits. At a strict cap the last legal position can predict a next token; processing that next token would require a new slot. A runtime can stop, reject, truncate and re-prefill, or use a supported sliding policy. Eviction alone does not extend a model’s trained positional range.

Sliding deletes explicit access to old keys and values. Surviving higher-layer rows can still contain information mixed from earlier positions. Continuing with an evicted cache therefore differs from re-prefilling only the retained text. We keep absolute positions in the toy traces.

02 / THE REPRESENTATION

Same attention idea.
Different cached state.

MHA, GQA and MQA change which query heads share stored keys and values. MLA factorizes the representation itself. All can retain multiple query heads; fewer stored heads does not mean fewer queries.

2.1 MHA → GQA → MQA

For H query heads and G KV heads, head h reads g(h) = ⌊h/(H/G)⌋. MHA sets G = H; MQA sets G = 1; GQA chooses a divisor between them. Shared K/V are stored once and reused, rather than physically duplicated for each query.

ah = softmax(QhKg(h)ᵀ / √dh),   oh = ahVg(h)
cache = 2 · L · T · G · dh · b bytes   (one sequence)

Reducing G constrains the independent KV representations a trained model can use. You cannot turn a trained MHA model into a quality-preserving GQA model just by averaging its caches. The GQA paper uses an uptraining procedure; this lab compares storage mechanics with separately initialized weights, not language quality. GQA ↗ · MQA ↗

2.2 MLA: attend in a shared latent space

Store a compressed content vector cj, then let each head have its own learned expansion into content keys and values. The full K/V still exist mathematically, but need not be materialized during efficient inference. Keep a small, separate positional key for decoupled RoPE.

cj = ujWDKV ∈ ℝr;   kCj,h = cjUKh;   vj,h = cjUVh
st,j,h = [qCt,h · kCj,h + qRt,h · kRj] / √(dC + dR)
cache = L · T · (r + dR) · b bytes

In row-vector notation, q(cUK)ᵀ = (q(UK)ᵀ)cᵀ. Move the key up-projection onto the query once. Likewise Σ aj(cjUV) = (Σ ajcj)UV: aggregate the latents first. The value expansion can then combine with the output projection. This is algebraic rearrangement within an MLA model, not lossless compression of arbitrary MHA caches.

Why ordinary RoPE interferes with absorption

A position-dependent rotation inserted between a key up-projection and a dot product generally cannot commute through an arbitrary learned matrix. MLA separates position-bearing Q/K dimensions from the content dimensions so content attention can use absorbed weights. DeepSeek-V2 also has query compression and other architectural details absent from this compact architecture trace.

03 / THE GENERATION LOOP

Predict more.
Verify what survives.

Autoregressive dependencies still exist. Faster decoding proposes multiple future tokens cheaply, then uses the target model to decide which prefix can be committed.

3.1 Speculative decoding and cache rollback

A cheap draft proposes y₁…yk. A target evaluates the candidate block with a causal mask. Distribution p₁ comes from the existing prefix’s final logits; p₂ comes after processing y₁, and so on. Greedy verification accepts while yi = argmax(pi). At the first mismatch it emits the target’s token and discards the remaining candidates.

accepted prefix length m = first mismatch index − 1
commit cache length = old prefix length + m
idealized tokens per cycle = m + 1;   speed ratio ≈ (m+1)ttarget,1 / (k tdraft,1 + tverify,k + overhead)

Verification can evaluate known candidates in parallel within each layer, like prefill. It cannot make the unknown true future tokens independent. Rejected rows must be removed from every layer’s K and V cache. When all k candidates pass, the last candidate’s logits provide a bonus token. That bonus or correction token does not have a cache row until it is fed through the decoder.

3.2 Greedy matching is not exact stochastic sampling

For sampling, a draft distribution q proposes y. Accept it with probability min(1, p(y)/q(y)). If rejected, sample from the normalized positive residual [p−q]+. At every conditional position, this restores the target distribution p exactly in ideal arithmetic. Just keeping tokens that look “likely” would generally bias the output.

P(accepted token = j) = q(j) · min(1,p(j)/q(j)) = min(p(j),q(j))
α = Σj min(p(j),q(j)),   r(j) = max(p(j)−q(j),0)/(1−α)
P(output = j) = min(p(j),q(j)) + (1−α)r(j) = p(j)

If α = 1 there is no rejection and the residual is unused. Draft tokens with q = 0 cannot be sampled by the draft, but can appear through correction. The identity applies to the target distribution after its sampling transformations. Speculative sampling paper ↗

A four-token categorical toy computes the probability identity, plus 20,000 reproducible sampling trials. Distribution equality does not mean the same token sequence under an unrelated random seed.

3.3 Multi-token prediction: train future heads

Ordinary training predicts xt+1 from ht. A simple MTP model adds a head for xt+2 using the same hidden state. Both heads can run together; the second is guessing the future before it sees the first generated token. Their marginals are not the exact joint autoregressive distribution.

p₁ = softmax(htW₁),   p₂ = softmax(htW₂)
ℒ = CE(p₁,xt+1) + λ CE(p₂,xt+2)
p₂(xt+2 | prefix) ≠ p(xt+2 | prefix, actual xt+1) in general

Auxiliary predictions can train richer representations or supply self-speculative proposals. To retain the base model’s sampling distribution, use a valid verification/correction scheme. DeepSeek-V3’s MTP uses sequential modules with shifted token embeddings, a more involved design than these independent heads. Multi-token prediction ↗ · DeepSeek-V3 ↗

04 / STATE ACROSS REQUESTS & MODELS

Reuse the work.
Respect the representation.

Moving KV bytes and translating KV meaning solve different problems. Exact reuse depends on the same causal computation; cross-model reuse needs a compatibility argument and downstream checks.

4.1 Same-model transfer versus cross-model translation

With identical weights, adapters, prefix token IDs, positions, attention rules and numeric format, a cache can move from a prefill worker to a decode worker. The receiver also needs request metadata, and either the final logits or enough state to compute the first output. Transfer time is roughly bytes/link bandwidth plus serialization and scheduling; skipping compute is helpful only if that cost is smaller than recomputation.

same-model handoff: Creceiver = Csender (compatible computation)
cross-model mapping: Ĉtarget = f(Csource) ≈ Ctarget
ridge: W* = argminW ‖XW − Y‖²F + λ‖W‖²F
W* = (XᵀX + λI)−1XᵀY

X contains aligned source rows; Y contains target rows for the same token positions. Fit K and V per head/layer. In code, solve the linear system rather than explicitly forming the inverse. Strip a source key’s RoPE rotation before fitting a position-free content map, then apply the target rotation after mapping. Different tokenizers, layer counts and head layouts require additional alignment.

4.2 Prefix reuse is exact only at a shared causal prefix

If two requests begin with identical token IDs under the same computation, the shared prefix has identical K/V. Reuse those rows and prefill only the suffix. If an earlier token changes, every later cached position may change—even if later text is identical. A shared paragraph in a different preceding context is not a reusable prefix.

P = longest_common_prefix(A,B)
reusable rows = P   (token-exact cache);   ⌊P / block_size⌋ · block_size   (full-block cache)
cache key must identify the model/configuration and the causal token prefix

05 / THE MEMORY BUDGET

What to keep.
How to store and read it.

Eviction changes accessible evidence. Quantization approximates numbers. Paging changes placement. FlashAttention changes execution. These operations can be combined, but their guarantees differ.

5.1 Eviction: spend a finite row budget

A recent window keeps locality but may remove an early fact needed now. A sink+recent policy reserves initial tokens to stabilize attention behavior and uses the remaining slots for recent text. Heavy-hitter policies estimate importance from accumulated attention, typically retaining important rows plus recent ones. Current attention is not a guarantee of future relevance.

importancej = Σpast queries t Σheads h at,j,h
retained = recent rows ∪ top-ranked historical rows, subject to budget
after eviction: a′j = exp(sj) / Σk∈retained exp(sk)

Dropping one row renormalizes all remaining attention weights. A sink is an attention role, not necessarily a useful fact. Actual StreamingLLM/H₂O policies have model- and implementation-specific details; this lab uses a shared row set across heads/layers to make the effect visible. StreamingLLM ↗ · H₂O ↗

LAB 05A

Remove rows before the answer query

The final prompt query is always included in the budget. We evict immediately before processing it; earlier surviving hidden states are preserved. Heavy-hitter scores use earlier queries only, averaged across both layers. This is one controlled continuation, not a long-run eviction benchmark.

5.2 Quantize the cache, then measure attention error

Map a floating-point vector into b-bit integer levels and retain enough metadata to reconstruct an approximation. A smaller cache reads fewer payload bytes but incurs dequantization, scales, and possible accuracy loss. Key error affects the matching distribution; value error affects the retrieved vector.

s = (max(x) − min(x))/(2b−1),   q = round((x − min(x))/s)
x̂ = min(x) + s q;   Δscore = qquery · (k̂ − k)/√d
payload bits = N · b;   actual storage = payload + scale/offset metadata + alignment

This is per-vector affine scalar quantization. KIVI motivates different grouping for keys and values and keeps a high-precision residual region; its full algorithm is not implemented here. KIVI ↗

5.3 PagedAttention: logical order, physical blocks

Allocate fixed-size KV blocks as a sequence grows. A block table maps its logical token blocks to physical memory. Attention follows that mapping in logical order, so fragmentation does not alter the math. Share immutable prefix blocks across requests; copy a shared partially filled block before extending it (copy-on-write).

logical_block(t) = ⌊t/B⌋,   offset(t) = t mod B
physical_row(t) = block_table[logical_block(t)] · B + offset(t)
allocated slots = ⌈T/B⌉B;   unused tail slots = ⌈T/B⌉B − T
LAB 05C

Address-allocation simulator, not a GPU serving kernel. It shows one request and fragmentation; Lab 04B shows prefix sharing eligibility. Paging does not itself evict tokens, quantize values, or reduce dense attention work. PagedAttention ↗

5.4 FlashAttention: exact attention without a full score matrix

Process K/V in tiles and update a running maximum m, normalization sum ℓ, and unnormalized weighted output o. When a new tile has a larger maximum, rescale the previous partial result. The final o/ℓ equals dense softmax attention up to floating-point rounding, without storing all scores in GPU high-bandwidth memory.

m′ = max(m, max(stile));   β = exp(m−m′)
ℓ′ = βℓ + Σ exp(stile−m′)
o′ = βo + Σ exp(stile−m′)vtile;   result = o′/ℓ′

06 / KEEP GOING

The next questions
to investigate.

Use these as extensions of mechanisms already tested above. Each adds an extra assumption or a different tradeoff.

Rotation-based quantization

For orthogonal R, (qR)·(kR) = q·k. Rotation can spread outlier energy before low-bit quantization; approximation error appears when coordinates are rounded. TurboQuant combines more than this identity, including distinct compression/estimation machinery. The lab below isolates rotation plus rounding.

x′ = xR;   x̂ = quantize(x′)Rᵀ
TurboQuant (2025) ↗

Cross-layer cache sharing

Some architectures learn to reuse KV across layers rather than storing independent rows for every block. If only S layers produce KV, storage can scale like 2TGdhbS rather than 2TGdhbL. Existing layer caches cannot simply be identified with each other; the model must support the sharing scheme.

Cross-layer attention ↗

Sparse retrieval of cache rows

A selection mechanism chooses a subset Jt before expensive attention: o = Σj∈Jₜ softmaxJₜ(s)jvj. Selection can reduce reads while preserving unselected rows in storage, unlike eviction. Missing relevant rows changes the answer; the indexer’s own cost matters.

DeepSeek sparse attention implementation ↗

Chunked prefill and scheduling

Split a long prompt into chunks to interleave prefill and decode requests. With the same causal mask, positions and exact cached state, final logits should agree with unchunked prefill. Chunking changes scheduling and peak temporary memory, not the number of prompt KV rows.

THE EVIDENCE & THE LIMITS

Reproduce the mechanics.

The course decoder has 23 tokens, two layers, width 32, four heads of width 8, a width-64 gated MLP, and a 32-token runtime cap. Training uses the fixed three-key order shown in the presets, with a disjoint split of value assignments reserved for evaluation. Training sequences fit inside that cap; no claim is made for extrapolation, general conversation, production latency, or pretrained-model transfer. The model weights are stored as FP32 values; JavaScript evaluates them in double precision. The architecture trace remains the original untrained CUDA experiment.
